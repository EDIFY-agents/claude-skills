01 / The problem

AI changes are fast to produce. They are still expensive to trust.

A frontier model with a plain setup writes excellent code and still stumbles on serious repositories. Not from lack of intelligence. From three things that happen on every large codebase.

Lost map
The agent explores the repo again. Every session starts blind and re-derives the same structure, slightly differently each time.
Drift
Each session reinterprets the work. The same task, done in parts, in different ways, with decisions silently re-made.
Looks right
The change passes a glance and is wrong. It breaks an intent, an architectural boundary, a version, or a dependency nobody wrote down.

07 / Local-first

Your code stays your code.

There is no telemetry. Not anonymous, not aggregate, not opt-out. Nothing reports what you ran, where you ran it, or that you installed it.

No account required, ever, including for the free plan.
The graph and every artefact live in your repository.
Zero runtime dependencies. Nothing in the supply chain but Python.
Feedback writes a file on your machine; you decide whether to send it.
Hard gates, if you want them, live in the CI your team controls.

FAQ

The questions people ask first.

Q1Is this another coding agent?+

No. EDIFY does not host a model, wrap an agent runtime, or route between providers. It gives the agent you already use better context, an explicit plan, and independent verification. Cancel your agent subscription and EDIFY does nothing at all.

Q2How is it different from Spec Kit?+

Spec Kit is the closest free alternative and a good tool. The differences: a codebase graph extracted mechanically, never by a model; verification-first builds, with failing tests before core logic and a /verify session that wrote no code; and agent-agnostic by construction.

The honest answer to "which is better" is the benchmark, which has not finished running.

Q3Does it send my code anywhere?+

No. There is no telemetry of any kind. Only edify upgrade and edify self update open a socket, both by your explicit action. Your agent still talks to its own vendor; EDIFY is not in that path.

Q4Is it worth it for a small project?+

No, and we would rather say so. A frontier model in auto mode is already excellent on a small codebase. The value starts where the repository stops fitting in the context window.

Q5Does it block bad changes?+

Not by itself, and that is deliberate. edify check prints; you or your CI decide what it means. --exit-code is how you build a gate you own.

Q6Is it open source?+

It is source-available under the Functional Source License (FSL-1.1-Apache-2.0), free for any use except building a competing product. Every released version becomes Apache 2.0 two years after release.
